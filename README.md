# カスタムjs → ランチャー対応 変換（試作 v0.1.1・2026-11-25）

Dancing☆Onigiri (CW Edition) の既存のカスタムjsを、ランチャーの規格（v0.3）に合わせて書き換える道具です。
ランチャーは、[danoniplus-plugins](https://github.com/cwtickle/danoniplus-plugins) の `_launcher` にあります。

## できること

全自動ではありません。**候補を見つけて、人が選んで、機械が書き換える**道具です。

| 段階 | 中身 | 機械がやる範囲 |
|---|---|---|
| 1. 登録だけ | 宣言（id・名前・版）と、二重読み込みの確かめ・登録を足す | 全部 |
| 2. 定数を設定に | 冒頭の定数と、設定用オブジェクトの値を、ランチャーで変えられる設定にする | 候補を出す・書き換える。どれを設定にするか・範囲・ラベルは人が決める |
| 3. 案内だけ | 本体の設定画面への追加・自前のボタン・自前の保存 | 場所と直し方を出す。書き換えない |

### 候補になるもの

冒頭（全体を包む即時関数の直下。包んでいなければファイルの直下）の宣言のうち、値がそのまま書かれているもの。

- `const BAR_H = 10;` のような定数（true / false・数・文字）
- `const C = { blue: '#2a3754', size: 3 };` のような、設定用オブジェクトの中の値
  （`window.g_x = { … }` へ同時に入れる形・`Object.freeze({ … })`・入れ子も見る）

型は値から決めます。true / false → オン／オフ、数 → 数（または選択）、`#rrggbb` → 色コード（または選択）。
ほかの文字は、選択肢を人が並べたときだけ「選択」にできます（規格に、文字を自由に入力する型が無いため）。

### 書き換えのしかた

- **定数**は、宣言を外して、読んでいる所を `def.values.◯◯` に差し替えます。同じ名前の別の変数（関数の引数など）は触りません。
  上と横に書かれた注釈は、宣言の設定の行の上へ移します（ラベルの下書きにも使います）。
- **オブジェクトの値**は、その場所を `get ◯◯() { return def.values.◯◯; }` に差し替えます。読んでいる所は元のままです。
- **設定から計算している定数**（`const BAND_H = BAR_H + 24;`）は、使うたびに計算する関数に直します（外せます）。
  足し算や `Math.◯◯` だけの式に限ります。配列やオブジェクトを作る式は直さず、注意を出します。
- 構文木（acorn）で場所を決めて、その場所の文字だけを差し替えます。ほかの所（注釈・字下げ・改行の種類・BOM）は元のままです。
- 書き換えたあと、正しい js になっているかを確かめてから出します。

### 注意として出すもの

- **読み込みのときに 1 回だけ読んでいる所。** ランチャーは後から値を入れるので、そこには届きません。行の番号つきで出します。
  読み込みのときにだけ呼ばれる関数の中で読んでいる所も出します（v0.1.1。`let type = loadType();` の `loadType` の中、など。
  冒頭で名前を付けた関数のうち、その場で呼ぶだけで、フックに渡したりほかへ入れたりしていないものを、そう見なします）。
- 途中で書き換えられている変数（設定ではなく、状態を持つ変数かもしれない）。
- 旧式の書き方（`function customTitleInit()` を直に書く形）。全体は包まず、宣言だけを固有の名前（`g_plugin_◯◯`）で足します。
  このとき、外した定数をほかのファイルから読んでいれば、そちらも直す必要があります。
- 宣言が規格の決まりに合わないとき（id・key の形、数の範囲と刻み、選択肢）は、書き換えません。
  決まりは、ランチャー 1.0.0 の検査と同じにしてあります（`src/validate.js`）。

### やらないこと

- 値が変わったその場で画面に反映する処理（`onChange`）を作ること。下書きの行（注釈）だけ入れます。
- 全体のスイッチ（`enabled`）を自動で足すこと。OFF にしたときの後始末を機械では書けないためです。
- 本体の設定画面への追加や、自前のボタンを、ランチャーへ移すこと（案内だけ）。
- 旧式の関数を `g_customJsObj.◯◯.push` の形に直すこと。

## 使い方

### ブラウザ

[公開ページ](https://kwbredda3.github.io/danoni-plugin-converter/) を開きます。手元に置いたものは、`index.html` を http で開きます（`file://` では、部品を読み込めません）。貼った js はページの中だけで処理し、どこにも送りません。

手元で試すときは、このフォルダで `python -m http.server 8000` を動かして、http://localhost:8000/ を開きます。

### コマンドライン

```
node cli.mjs analyze <元の js>                           # 候補と、気を付ける所を JSON で出す
node cli.mjs convert <元の js> <指定の json> -o <出力>     # 指定どおりに書き換える
node cli.mjs convert <元の js> --auto --id <id> -o <出力>  # 候補を下書きのまま全部選ぶ（試し用）
```

指定の json の形は、`src/core.js` の `convert()` の説明にあります。

## 中身

| 場所 | 中身 |
|---|---|
| `index.html`・`style.css`・`src/app.js` | 画面 |
| `src/core.js` | 調べる（`analyze`）・書き換える（`convert`）。DOM もファイルも触らない |
| `src/scope.js` | 名前の参照を追う（どの宣言を指すか・関数の中か外か） |
| `src/validate.js` | 宣言が規格の決まりに合うかの検査 |
| `src/diff.js` | 行ごとの差分 |
| `src/sample.js` | 画面の「見本を入れる」の見本 |
| `vendor/acorn.mjs` | 構文解析（acorn 8.19.0・MIT。`vendor/acorn.LICENSE`） |
| `cli.mjs` | コマンドライン |
| `test/core.test.mjs` | 試験（`npm test`） |
| `test/make_check_page.mjs` | 実物のランチャーで確かめるページを作る（作者の手元用。本体とランチャーの試作が、このフォルダの隣に要る） |

組み立て（ビルド）は要りません。フォルダをそのまま置けば動きます。
